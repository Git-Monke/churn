# Churn server dashboard

A small TypeScript app that puts the Jellyfin library, the health of Jellyfin,
Sonarr and Radarr, the live VPN leak status of the torrent stack, and
search/requests for new media in one place.

```
server/
  backend/    Fastify API + serves the built frontend
  frontend/   React + Vite SPA
```

The backend is a BFF: it reads Jellyfin, Sonarr and Radarr APIs, keeps no
database, and never exposes upstream URLs or API keys to the browser. The
frontend only calls `/api/*` on the backend. Login sessions are held in process
memory, so restarting the backend signs everyone out.

## Requirements

- Node.js 22 or newer
- The `server` stack running (Jellyfin, Sonarr, Radarr)
- Churn to finish Jellyfin setup and create the API key (see below)
- A Jellyfin user account to sign in with

## Install and run

```bash
cd server
npm install
npm run dev
```

- UI: <http://127.0.0.1:5173>
- API: <http://127.0.0.1:4000>
- Vite proxies `/api` to Fastify during development.

Production build:

```bash
cd server
npm run build
npm start
# open http://127.0.0.1:4000 — Fastify serves the built SPA
```

The app binds to `127.0.0.1` by default and requires a Jellyfin login. The
browser-facing video URL defaults to the host's LAN address, so playback works
from other devices on the LAN; the backend still reaches Jellyfin over
loopback. For access from other machines, put the app behind a reverse proxy
with TLS; set `CHURN_COOKIE_SECURE=true` (or rely on `auto` with forwarded
HTTPS) so the session cookie is marked `Secure`. The Vite dev server is also
reachable from the LAN (`host: true` in `frontend/vite.config.ts`); pass
`--host 127.0.0.1` to keep a session loopback-only.

### Live torrent progress

The backend reads qBittorrent's stable `[WebUI]` API key from
`torrent/config/qbittorrent/qBittorrent/qBittorrent.conf` (falling back to the
legacy `WebUI\APIKey` entry). Set `QBITTORRENT_API_KEY` to override it, or
`QBITTORRENT_URL` when qBittorrent is not reachable at
`http://127.0.0.1:8080`. The key is used server-side only, for live progress,
duplicate recovery and untracked-download detection; it is never sent to the
browser. Activity and Library download status come from qBittorrent; the arr
queues are not used for UI status.

If Sonarr or Radarr reports a qBittorrent connection failure even though the
torrent is already present in qBittorrent, churn recognizes the misleading
duplicate error, removes the duplicate without deleting its files, waits for
qBittorrent to drop it, and retries the grab through the arr so the download
becomes tracked. The show page also matches qBittorrent torrents to their series
and season/episode from the torrent name, so live progress appears even when
Sonarr has no queue record for the download.

### VPN status

The Services page has **Services** and **VPN** tabs. The VPN tab calls
`GET /api/vpn`, which asks the torrent stack's `vpn-status` agent to run the
same checks as the fail-closed `vpn-check` container. The agent shares
Gluetun's network namespace, so the result describes qBittorrent's live path.
It returns the Mullvad exit IP/location/server, the DNS resolver, the kill
switch result, IPv6 state, the local firewall exception, and whether
qBittorrent, Prowlarr and FlareSolverr answer on their loopback ports.

The agent listens on `127.0.0.1:8098` only. If the torrent stack is not running,
the tab shows an actionable error instead of failing. Start it with:

```bash
cd torrent && docker compose up -d --no-deps --force-recreate vpn-status
```

If Gluetun itself was recreated, recreate the whole torrent stack instead:
`docker compose down && docker compose up -d`.

### Jellyfin setup and API key

After starting the server stack, churn talks to Jellyfin's HTTP API to finish
first-run setup:

1. It prompts for a Jellyfin admin username and password if Jellyfin is not
   configured yet. The password is not saved by churn.
2. It creates the first admin, completes the startup wizard locally with remote
   access disabled, authenticates, and creates an API key named `churn`.
3. It creates or repairs the `Movies` and `Shows` libraries at
   `/data/media/movies` and `/data/media/tv`. Any `/data` library path is
   removed, because qBittorrent downloads under `/data` and Jellyfin would
   otherwise index files that are still downloading.
4. It adds the private LAN ranges and Tailscale's reserved CGNAT range
   (`100.64.0.0/10`) to Jellyfin's LAN networks. Jellyfin replaces its default
   local-network detection once that list is non-empty, so churn keeps the
   private ranges explicit. Tailnet clients can then reach Jellyfin for direct
   playback while remote access stays disabled. Jellyfin applies this on
   startup, so churn restarts it after changing the settings.
5. It writes the key to `server/.env` as `JELLYFIN_API_KEY`. The backend reads
   that file on startup; restart it if it is already running.

Reruns are idempotent: a valid existing key is reused. If the key is missing or
invalid, churn authenticates with the admin credentials and creates/reuses the
`churn` key.

For non-interactive provisioning, set `JELLYFIN_ADMIN_USER` and
`JELLYFIN_ADMIN_PASSWORD` in the process environment or `server/.env`. These are
only installer inputs, not backend settings; the password is never written back.

If you configure Jellyfin manually, create a key under Dashboard → API Keys and
put it in `server/.env`, then restart the backend.

## Authentication and sessions

Every page except the login screen is behind a Jellyfin login. Churn validates
the username and password with Jellyfin (`/Users/AuthenticateByName`), stores
the returned user access token in a server-side session, and writes an opaque
`churn_session` cookie. The cookie is `HttpOnly`, `SameSite=Lax`, path-scoped
and set with `Secure` when Churn is served over HTTPS. Passwords and Jellyfin
access tokens never reach the browser for normal API calls.

Sessions live in a TTL Map in the backend process, keyed by a SHA-256 hash of
the cookie value. There is no database and no session file: restarting the
backend signs everyone out. The default idle TTL is 12 hours; the cookie itself
is kept for 7 days and is replaced on the next login. `POST /api/auth/logout`
clears the cookie, destroys the session and makes a best-effort Jellyfin logout
call.

All logged-in Jellyfin users get the full dashboard. That means any valid
Jellyfin account can search, request media, grab releases, and cancel/delete
titles, which changes global Sonarr/Radarr state. Jellyfin still enforces its own library access
because library and show requests use the user's token, but Churn adds no
admin-only gate of its own. Use separate Jellyfin accounts with non-admin
permissions if you want to limit library visibility.

Auth responses are `no-store`. Failed logins are throttled to 10 attempts per
15 minutes per IP and username. Cross-origin state-changing requests are
rejected in addition to `SameSite=Lax`. Playback uses the signed-in user's
session token, so resume positions and watched state are per Jellyfin user; no
static playback token is stored in `.env`.

| `GET /api/auth/session` | Current session state (200 even when signed out) |
| `GET /api/status` | Jellyfin/Sonarr/Radarr health, version and latency |
| `GET /api/vpn` | On-demand VPN leak test from inside the torrent stack's network namespace |
| `GET /api/library` | Jellyfin movies and series with backend-owned poster URLs and provider ids |
| `GET /api/library/images/:itemId` | Poster proxy; no Jellyfin key reaches the browser |
| `GET /api/library/requested` | Sonarr/Radarr library titles, including requested items not yet downloaded |

| `DELETE /api/library/jellyfin/:itemId` | Delete a Jellyfin-only title and its files, or use the matching arr title when one is found |

| `POST /api/library/movies/:id/releases/refresh` | Start a fresh per-indexer Prowlarr movie search |
| `POST /api/library/movies/:id/releases/grab` | Send the chosen torrent or magnet directly to qBittorrent |
| `GET /api/library/shows/:source/:id` | Jellyfin/Sonarr show detail with seasons, episodes and download overlays |
| `GET /api/library/shows/:source/:id/releases?season=N` | Progressive per-indexer Prowlarr search with live progress |
| `POST /api/library/shows/:source/:id/releases/refresh?season=N` | Start a fresh per-indexer Prowlarr search |
| `POST /api/library/shows/:source/:id/releases/grab` | Send the chosen season or episode torrent directly to qBittorrent |
| `DELETE /api/library/shows/sonarr/:id/episodes/:season/:episode/download` | Cancel that episode's active download, blocklist the release and keep imported files |
| `GET /api/playback/items/:itemId` | Playable item metadata, resume position, media source and same-origin stream URL |
| `GET /api/playback/items/:itemId/stream` | Redirect the media element to Jellyfin's direct stream URL for this session |
| `GET /api/playback/items/:itemId/hls.m3u8` | Redirect to a Jellyfin HLS transcode (H.264/AAC) when the source is not browser-compatible |
| `POST /api/playback/items/:itemId/start` | Report playback start to Jellyfin |
| `POST /api/playback/items/:itemId/progress` | Report playback position and paused state to Jellyfin |
| `POST /api/playback/items/:itemId/stop` | Report playback stop so Jellyfin keeps the resume position / watched state |
| `GET /api/activity` | Active qBittorrent downloads grouped by local library title |
| `GET /api/search?q=<term>` | Sonarr/Radarr lookup with Jellyfin availability and local catalog markers |
| `GET /api/search/images/:service` | Proxied arr media cover |
| `GET /api/requests/options` | Quality profiles, root folders and request defaults |

Errors use `{ "error": { "code": "...", "message": "..." } }`. Protected API
routes return `401 unauthenticated` without a session and `401 session_expired`
when Jellyfin rejects the stored user token.

## Search and requests

The Search section queries Sonarr and Radarr together with a debounced search.
Results already present in either app are marked **Available** when the arr has
the movie file or every series episode, otherwise **Requested**. Neither can be
added twice. Posters are proxied through the backend, so the browser never sees
an arr URL or API key.

**Request options** stores your preferred quality profile and root folder in
`localStorage`. The backend re-fetches metadata from the arr by id, validates the
selected profile and folder against the live API, checks for duplicates, then
adds the title unmonitored. It then starts the progressive Prowlarr release
search in the background: one movie search, or every regular season of a show in
season order, one at a time. Seasons Sonarr already has complete are skipped, so
opening a season later normally finds its results already cached. The metadata
Radarr/Sonarr returned
(title, year, TMDB/TVDB/IMDB
ids, seasons and poster) is cached under `server/cache/releases/media`, so the
release search can build its query without another arr lookup.

**Release search** is Prowlarr-first. The backend lists Prowlarr's enabled
indexers, sends one search per indexer in parallel, and returns each indexer's
results to the browser as soon as it finishes. The response includes progress
(finished/total plus per-indexer state), so the chooser can show
`5/9 indexers finished` and update while slower indexers are still running.
The chooser opens on the first result instead of waiting for every indexer.
Each release title is parsed by the target Sonarr/Radarr `/api/v3/parse`
endpoint, with a small in-process cache. The parsed title/year, season and
episode numbers, quality and season-pack flags are used to match the requested
media and reject unrelated names. Multi-season packs expand their title range
(`S01-07` covers every season) before matching. Results are grouped by quality
tier and sorted by seeders, then size.

Every enabled Prowlarr indexer is shown and results are grabbable directly even
when the indexer is not synced to Radarr/Sonarr. Choosing a release sends its
magnet or Prowlarr download URL straight to qBittorrent, tagged `churn-direct`.
qBittorrent saves into the existing Sonarr/Radarr folder: `Show/Season N` for a
single season or episode, the show folder for a multi-season pack, and the
movie folder for films. No arr release re-search or arr grab is performed.
When a `churn-direct` torrent finishes, the backend sees it in qBittorrent and
asks Jellyfin to scan once, so direct downloads do not depend on Jellyfin's
real-time monitoring. They are skipped by Sonarr scan recovery because they are
already in the library.

Release search snapshots persist under `server/cache/releases/prowlarr` (or
`server/.churn-cache/releases/prowlarr` when the container-owned `cache/`
directory is not writable). The first open of a title starts a search; later
opens show the snapshot until **Search again** starts a fresh one. Automatic
seeders-aware picking and swarm re-picks are retired from the request path.

Search stays usable when one app is down: the other app's results are still
returned and an alert explains the unavailable service.

## Library and activity

The dashboard is split into Services, Library and Search pages using lightweight
hash routes (`#/services`, `#/library`, `#/search`). Services has **Services**
and **VPN** tabs; the VPN tab runs its test when opened and on demand.

`/api/activity` reads qBittorrent's active torrents and matches them to the
Sonarr/Radarr catalog by title. It never reads the arr queues. Completed and
seeding torrents are excluded; progress, size, speed, ETA, season hints and
warning messages come directly from qBittorrent. The route keeps a short-lived
snapshot and caches the catalog for five minutes so the 500 ms Library poll stays
cheap.

The Library page merges `/api/library` (Jellyfin), `/api/library/requested` (the
local arr catalog) and `/api/activity` (qBittorrent):

- **Available** and play links require a matching Jellyfin item;
- **Downloading** requires an active qBittorrent torrent;
- **Requested** means the title is in the arr catalog but not Jellyfin/qBittorrent;
- **Scanning** is a non-playable transition while the arr has imported files and
  Jellyfin has not indexed them;
- active downloads sort before available titles;
- qBittorrent failures only show a download notice; arr failures only affect
  release search/request actions.

Every card has a trash button. Sonarr/Radarr-backed cards call
`DELETE /api/library/requested/:service/:id`, which removes queue records with
`removeFromClient=true`, deletes the movie or series with `deleteFiles=true`,
removes matching qBittorrent torrents the arr no longer knows about, and asks
Jellyfin to refresh. A follow-up refresh catches scans that started midway
through deletion.

Jellyfin-only cards call `DELETE /api/library/jellyfin/:itemId`. Churn first
looks for a Sonarr/Radarr title with the same provider id, or the same normalized
title and compatible year. If exactly one matches, it uses the arr delete.
Otherwise it deletes the Jellyfin item and its files, then removes matching
qBittorrent torrents. If the arr catalog cannot be checked, the Jellyfin delete
is refused instead of risking an orphaned arr entry.

The backend watches Sonarr/Radarr import history and qBittorrent for finished
`churn-direct` downloads. Either event asks Jellyfin to refresh, even when no
dashboard tab is open. While a Library card is **Scanning**, the page polls
Jellyfin every 2 seconds.

Movies stay at card level. Clicking a show opens
`/api/library/shows/:source/:id`, which unions Jellyfin and Sonarr episodes by
season/episode. Jellyfin alone marks an episode playable; a Sonarr file without a
Jellyfin episode is shown as **Waiting for Jellyfin**. Download progress comes
only from qBittorrent and is matched by torrent name, including season packs and
active upgrades. Jellyfin shows are matched to Sonarr through
`ProviderIds.Tvdb`; catalog-only shows use the Sonarr source directly.

Older arr-managed downloads can still finish before Sonarr imports them, so
churn asks Sonarr to scan those content paths. This recovers downloads whose
queue record was lost when a series was re-added or Sonarr restarted; the page
shows **Importing** while Sonarr matches the files. Torrents tagged
`churn-direct` are already in the Jellyfin library, so they are excluded from
Sonarr scan recovery; the direct-download watcher triggers Jellyfin's scan when
they finish instead.

Jellyfin can keep a series item while failing to link its on-disk episodes, for
instance after a restart or an interrupted import. When a Jellyfin show loads
with no episodes, the backend requests a library scan (at most once every five
minutes) and the page polls every two seconds while that scan is likely still
running, so the episode list fills in without a manual reload.

For shows tracked in Sonarr — including Jellyfin-backed shows — **Choose
release** runs the progressive Prowlarr season search. The chooser opens on the
first result and updates as each indexer finishes. Grabbing a single season
saves to `Show/Season N`; a multi-season pack is sent to the show folder and
Jellyfin groups its episodes by `SxxExx` names.

Missing individual episodes keep their own **Choose release** action, which runs
the same per-indexer Prowlarr season search and narrows the results to that
episode. An episode that is already downloading gets a
**Cancel download** action instead: it removes that episode's Sonarr queue
records and download client entry when available, or falls back to removing the
matched qBittorrent torrent, and leaves imported files alone. A season-pack
download cancels the whole pack, and the confirmation says so. Upstream GUIDs,
magnet URLs and indexer ids stay on the backend. A show that exists only in
Sonarr still opens a Sonarr-backed detail page.

## Playback

Movies in Library and episodes in show detail open `#/play/<itemId>`, an HTML5
`<video>` page backed by Jellyfin. Playback is per Jellyfin user: the item's
resume position comes from Jellyfin `UserData`, and start/progress/stop reports
keep Jellyfin's Continue Watching and watched state in sync.

Video bytes are not proxied through Churn. Playback is codec-aware:

- Browser-compatible sources use a same-origin
  `/api/playback/items/:itemId/stream` URL. The backend validates the session
  and returns a `302` to Jellyfin's `static=true` stream with the user's access
  token as `api_key`. Seeking works because Jellyfin serves byte ranges.
- Other sources (for example HEVC video with AC3 audio in an MKV) use a
  same-origin `/api/playback/items/:itemId/hls.m3u8` URL. The backend returns a
  `302` to Jellyfin's HLS manifest with explicit H.264/AAC transcode parameters
  based on the source resolution and bitrate. The frontend plays it with
  `hls.js`, with native HLS as a fallback.

If Jellyfin's transcode job stops because the source file has a damaged
section, the player retries transient network and media errors in place. If the
stream stays stuck, it recreates the HLS pipeline with an explicit start
position a few seconds ahead; that segment request makes Jellyfin restart FFmpeg
past the damaged keyframe. Retries skip further ahead (5s, 15s, then 30s) and
continue automatically even if the player emits no further error. Only after
those attempts does it show the interruption alert with a **Retry** action.

The token never appears in the page DOM or API responses, but it is visible in
browser devtools, redirect targets and Jellyfin HLS playlist/segment URLs. That
is the accepted tradeoff for stream redirection; a backend proxy would be needed
if Churn is exposed beyond the LAN.

By default the browser-facing Jellyfin URL follows the hostname used to reach
Churn. A loopback host or a single-label container name in `JELLYFIN_URL`
(`http://jellyfin:8096`) is replaced with the request host, keeping scheme, port
and base path. That makes the same install work through a LAN address, a
Tailscale IP or a MagicDNS hostname without extra configuration; the server
stack publishes Jellyfin on port 8096, so tailnet clients reach it the same way
they reach the dashboard. If `JELLYFIN_URL` is already a browser-routable name
it is used unchanged, and a request without a Host header falls back to the
detected LAN address.

Set `JELLYFIN_PUBLIC_URL` when the browser reaches Jellyfin at an address that
is neither the request host nor the detected LAN address, for example a reverse
proxy or a TLS name. An explicit value always wins. Preview the fallback in the
backend's startup log (`video streams follow the request host (fallback …)`).
Playback failures show the media error alert with an **Open Jellyfin** fallback,
except for an HLS interruption, which offers **Retry**.

## Container later

The app is environment-driven so it can be containerised later:

- `HOST=0.0.0.0` and join the server Compose network;
- use service DNS names, e.g. `JELLYFIN_URL=http://jellyfin:8096`;
- pass API keys via environment;
- if relying on `config.xml` discovery, mount
  `server/config/{sonarr,radarr}` read-only.
