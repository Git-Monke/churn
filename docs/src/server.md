# Server stack

The server stack is the media-facing half of the setup. It runs outside the
VPN because it serves the local library and provides the automation APIs used
by the torrent stack.

## Services

| Service | Role | Host port |
| --- | --- | --- |
| `jellyfin` | Media server and player frontend | `8096` |
| `sonarr` | TV series management and downloads | `8989` |
| `radarr` | Movie management and downloads | `7878` |
| `server-init` | One-shot setup for media folders and root folders | none |

## Storage

Every service mounts the same host directory as `${DATA_DIR}` at `/data`.
Jellyfin reads the media library from there, and Sonarr/Radarr use the same
paths for their libraries and completed downloads. Keeping one path layout
avoids translation between the two stacks.

`server-init` creates:

```text
/data/media/tv
/data/media/movies
```

It also sets ownership to `PUID`/`PGID` and registers those directories as the
Sonarr and Radarr root folders. The one-shot is idempotent and can be rerun:

```bash
cd server
docker compose run --rm server-init
```

## Configuration

`server/.env` is generated by churn and holds `DATA_DIR`, `PUID`, `PGID`, and
`TZ`. The compose file is static. Web UIs are published directly by each
service, so they are reachable at:

- Jellyfin: `http://<host>:8096`
- Sonarr: `http://<host>:8989`
- Radarr: `http://<host>:7878`

The torrent stack's `prowlarr-init` reads the Sonarr and Radarr API keys from
`server/config/`. This is why the current wiring expects both stacks on the
same machine.

## Dashboard

The optional TypeScript app in `server/backend` and `server/frontend` serves a
single dashboard for the Jellyfin library and the health of Jellyfin, Sonarr and
Radarr. It binds to `127.0.0.1` and the browser only calls the backend; upstream
keys and URLs stay server-side.

```bash
cd server
npm install
npm run dev        # UI http://127.0.0.1:5173, API http://127.0.0.1:4000
```

Finish Jellyfin's first-run wizard and add `JELLYFIN_API_KEY` to `server/.env`
to show the library. Sonarr and Radarr API keys are read from
`server/config/*/config.xml` unless overridden. `churn` should eventually
complete Jellyfin setup and create that key automatically; until then the
dashboard shows a setup notice.

The planned order is: library/status dashboard, search and media requests,
download/activity queue, then Jellyfin playback controls. See
[Web dashboard](web-ui.md) for the current API and configuration.
